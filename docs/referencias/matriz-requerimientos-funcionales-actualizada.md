## Datos de versión

Fecha de la Versión: 2026-06-30

Esta versión reorganiza la matriz funcional actualizada en módulos principales de negocio y mantiene la revisión cruzada con historias de usuario, casos de uso y pantallas visibles del sistema. Los requerimientos administrativos, públicos y del cliente que pertenecen al mismo dominio se encuentran ahora dentro de un único módulo y se diferencian mediante el nombre del subproceso.

## Resultado de agrupación

Se conservan 396 registros funcionales identificados en la revisión funcional y se consolidan los nombres de módulo originales en 16 módulos principales. No se eliminaron funciones ni reglas del negocio. Las columnas de numeración RF, RN y RI permanecen vacías para mantener la matriz alineada con el criterio documental vigente.

Por ejemplo, las funciones de `Checkout Pago`, `Pagos`, `Pagos Admin`, `Configuración de Pagos` y `Facturas Admin` se agruparon en `Pagos y Facturación`. La diferencia entre operaciones del cliente, checkout, configuración y administración se conserva en la columna `Subprocesos`.

## Criterios de redacción y agrupación

Cada módulo representa un dominio funcional amplio del sistema. La columna `Subprocesos` incluye primero el contexto funcional y después la acción específica, usando el formato `Contexto — Acción`. Esto evita crear módulos separados únicamente porque una función se ejecuta desde la tienda pública, la cuenta del cliente o el panel administrativo.

Los requerimientos mantienen la forma `El sistema debe...`. Cada fila conserva tres elementos relacionados: el requisito funcional indica el comportamiento esperado, la regla del negocio define sus condiciones o restricciones y el requisito de información enumera los datos necesarios para ejecutar o registrar la función.
